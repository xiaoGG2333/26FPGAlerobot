# 限位感知和有限初值重试 试验版本

## 实际执行顺序
先以编码器反馈为初值运行原位置优先LM，成功时立即返回，保留原收敛路径。
仅当返回未收敛时，尝试两组备用数值初值：肘关节分别偏移-10度和+10度，腕俯仰相反偏移；所有初值均限制在原有模型角度范围内。
备用求解启用活动限位：仅对已到边界且增量朝外的关节暂时约束，重新调用PL求剩余关节增量；每一步重新判断，允许向范围内返回。
两组备用求解各最多80次迭代，所有尝试共用600次硬件调用预算。多个备用解成功时，以相对当前姿态的归一化关节距离选择较近者。
计算种子不会发送给舵机。只有最终合格解才进入原有编码器与轨迹检查。
硬件错误、数值异常或非法ID5目标不执行备用重试；仍走原有错误处理。全部失败仍拒绝新目标，保持上一有效目标。

## 保留的内容
PS仍负责迭代和关节边界判断，PL仍负责雅可比、正规方程与单步线性求解。
不改舵机执行、轨迹、速度200..2000、Xbox5cm/s上限、夹爪、编码器映射、温控和故障扭矩策略。
PL在负阻尼选取的位置任务中，将原保留输入e5用作0..15的四轴约束位掩码；正阻尼全位姿模式与AXI地址布局保持不变。因此必须配套更新新BOOT，不能混用旧PL与新ARM程序。

## 离线结果
1878个目标对照，原成功目标无回退。250个合成可达目标中救回7个原失败目标，仍有5个未找到解。这不是全局完备求解器。
历史969个目标和最新日志659个求解目标的成功失败分组未改变。最新日志的初值由采样编码器近似重建，并非逐步精确录制，结果仅作对照参考。
独立数值后端对照不等于实板验证；另用真实HLS核验证全部16种掩码的约束方程，以及两例重试成功目标。
新方案可能增加失败目标的计算耗时，不能保证实物运动变快；也不能解决已证实几何不可达的目标。
RESULT1格式不变，iterations在重试时为各次尝试的累计迭代数，可能大于200；MAX_ITER仍表示未找到合格解，不能直接解释为几何不可达。

## 部署
旧BOOT与旧工程包均保留。新版应放在独立目录，先备份SD根目录BOOT.BIN，再在断电时以本包boot/BOOT.BIN替换，安全弹出后开机。
串口HELLO应包含BOUND_RETRY_IK_20261031_V1和SERVO_SPEED200_2000_20261031_V1。
更新包同步到Ubuntu并不等于板端已经更新。启动运动仍按原流程确认，本次构建不自动使能舵机。

```bash
source ~/venvs/joycon-rk7020/bin/activate
cd ~/rk7100_so101_bound_retry_20261031
python -u host/xbox_control.py --port /dev/ttyUSB1 --xbox-device /dev/input/event6 --xbox-right-axes rxry --test-drive --manual-control --translation-speed 0.05 --hz 10 --gripper-control --gripper-config host/gripper_config.json --csv results/bound_retry_drive.csv
```

失败后可以继续输入范围内目标。Ctrl+C或明确STOP沿用原关闭扭矩处理。
