# Zynq SO101 工程验证

## 实机证据按版本登记（2026-11-02）

FPGA 逆解工程已进入实机验证。RK7020 已有双核逆解用例结果，RK7100 已有板端遥测、六轴舵机读回及 Xbox 保持和停止记录。限位重试版与 2025.2 候选版分别引用各自的验收记录。手势识别列为后续扩展，尚未进入实机验证。详见 [实机证据与版本边界](references/evidence.md)。

以用户指定的工程与版本为准。先读工程 AGENTS.md、版本指南、源文件和对应报告；历史参数只能用于解释历史结果。此技能不授予硬件运动、写EEPROM、烧录或发布权限。

- 写报告或说明效果：读 [证据与边界](references/evidence.md) 和 [协作案例](references/collaboration-cases.md)。

## 项目关键事实

RK7020_So_101 目录当前目标是 RK-ZYNQ7100-F，器件 xc7z100ffg900-2；不要根据目录名选择7020器件。PS负责完整迭代、轨迹与舵机控制；PL负责单步数值求解，两个核的地址为0x40000000、0x40010000。不能仅因存在双核就声称生产路径双核并行。

当前任务为XYZ位置与ID5关节角，末端俯仰自由；模型端点不是夹爪尖端。用实际源文件确认坐标和工具点，再解释移动方向或抓取精度。架构详情见 [架构](references/architecture.md)。

## 执行原则

1. 记录待检查版本、输入、期望输出和对应报告，先完成不接触硬件的分析。
2. 沿输入目标、IK结果、编码器目标、轨迹命令、实际反馈逐层定位。求解成功不等于机械臂已到达；失败代码不等于全局不可达。
3. 数学/控制修改分开比较。保留用户要求不变的映射、温控、夹爪、扭矩和故障策略，使用差异或哈希验证。
4. 编译、离线数值测试、RTL协同仿真、板端计算与实物运动分别记录；后一层不能由前一层代替。
5. 对故障重试先确定上限和退出条件。不要把数值备用初值下发给舵机，也不要为消除报错而扩大限位或屏蔽保护。
6. 如需实物动作，遵循本次用户授权和现场状态；历史授权不代表本技能可以自动启动机械臂。构建检查与日志分析保持无运动。

## 输出要求

输出结论、证据路径、替代解释、验证边界和下一步。对无法从日志判定的问题，说明还缺哪一层数据。手势识别仅为后续扩展，未验证，不列入现有功能。

使用 `python skill/zynq-so101-validation/scripts/check_evidence.py --project-root <工程目录>` 核对本次提炼所依据的文件快照。该脚本只读文件，不运行工程测试、不连接板卡；哈希一致不等于功能正确。
