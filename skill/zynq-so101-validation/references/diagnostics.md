# 分层诊断：目标、求解、执行

## 最小证据

记录固件HELLO、命令与序号、目标XYZ/ID5、求解初值/终值/残差/状态、原始与目标计数、轨迹中间点、总线反馈、温度和扭矩状态。日志没有某字段时标记缺失，不补造。对比时间戳和采样时刻；停止后的直接读取可能与停止前缓存不同。

## 诊断决策

1. 输入：设备轴是否正确？死区是否吞掉输入？PREVIEW ONLY不驱动。识别到手柄不代表已启用运动。
2. 通信：HELLO是否匹配？有无重复进程占口、错误接口或超时？先只读枚举；不要用反复启动运动测试连通性。
3. 求解：目标实际是否变化？成功时检查最终q与残差；iter=0通常是输入已在容差内。MAX_ITER可由试步无法改善提前结束，不一定耗尽200步。
4. 映射/轨迹：q→计数是否通过整体检查？目标、waypoint、actual三者哪个停住？错误码可能合并模型/轨迹拒绝，需要读具体分支。
5. 执行：五轴目标存在不等于五轴收到或执行。检查同步总线命令、反馈、模式、扭矩和负载。目标队列标签不证明总线已写入。
6. 时序：分开看输入周期、往返、IK计算、总线刷新和物理到达。roundtrip不能直接作为纯逆解时间；没有收发计数或积压证据时不能断言串口溢出。

## 不可达判定

到关节边界不等于目标不可达；要区分当前分支、局部求解失败和几何必要条件不满足。用同一模型、参考点、限位和容差检查距离上界/基座平面等条件，考虑其他分支。备用初值只提高找到解的机会，不提供完备性证明。不允许用任意裁剪五轴目标来伪装到达原末端目标。

## 结束输出

给出支持最强的原因、可排除的原因、尚缺证据和最小下一步。不要用提高舵机速度来解决未证实的单轴不跟随，也不要把所有异常统一归因逆解。
