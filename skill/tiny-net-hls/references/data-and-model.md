# 小网的训练与数据

这些结论来自「同一个网络结构、同一套损失、只换数据」的对照实验，可直接当作初始假设。

## 1. 先换数据域，再换结构

同一份代码、同一次训练预算，只把数据从「网络图片」换成「部署场景自采」：

| 指标 | 网络图片 10k | 域内自采 3k |
| --- | --- | --- |
| 平均误差 | 0.1005 | 0.0363 |
| 中位 / p90 | 0.0592 / 0.2324 | 0.0366 / 0.0478 |
| 崩溃率（误差 > 0.15） | 17.7% | 0.3% |
| 角度误差 | 6.41° | 3.54° |

而换输出头（GAP 回归 → 热图）在同一份数据上只带来 0.1167 → 0.1005，约 10%。

**规则**：指标差 3 倍以上时，先看数据域（相机、距离、视角、光照、姿态覆盖），不要在结构上找原因。域内 3k 能打赢域外 10k。

## 2. 单一录制不是超集

用一段只包含「张开手掌」的新录制从头重训，模型会**忘掉**之前覆盖的握拳/抓握姿态——不是 bug，是覆盖度回归。任何从头重训都必须覆盖完整的部署姿态集；新录制只能当**增量**，按样本数自然加权合并进旧缓存（宽的那份占主导）。

## 3. 划分只能按连续段

相邻帧高度相关。随机分帧会让验证集泄漏到训练集里，指标虚高。按**连续段落/视频块**切（70/15/15），并把 segment + frame 索引一起存下来，方便以后做时序一致性相关的实验。

## 4. 正负样本配比

图像缓存如果只保留「有目标」的样本，**presence 头永远学不会否定**：任何框都会输出「有手」，demo 只能在框里画出幻觉骨架。做法：

- 从一段确定没有目标的窗口里采几百张负样本（`presence=0`，坐标/类别损失用掩码屏蔽，只算 BCE）。
- 负样本的裁剪位置要打散（帧数常常不够，同一帧不同位置也算不同样本）。
- **每张负样本都要用教师模型复检一遍**，命中就丢弃并计数。真实事故：负样本通道读帧时没有 seek 到声明的窗口，于是「负样本」其实是从头开始的近景正样本，只有靠缩略图肉眼检查才发现。

## 5. 尺度统计量必须每次重算

给推理端用的「目标尺度中位数」必须从**当前缓存的阳性样本**重算，并且随模型一起传递参数。两个坑：

- 全样本分位数会被负样本的 0 值污染（p5 变成 0）；
- 不同数据集的这个中位数差别很大（一张脸/手前伸的录制 0.42，摊开手掌前伸的录制 0.30，480p 相机录的 0.26）。

写死常数 → 推理端裁剪框尺度系统性偏大或偏小。

## 6. 输入里的「目标像素数」才是分辨率决策依据

判据不是图像边长，而是目标在输入里占多少像素：

```
目标像素 ≈ 输入边长 × (目标尺寸 / 裁剪框边长)
```

用「下采样到 N 再上采样回原尺寸」的代理实验可以直接回答「降分辨率掉多少」——实测 224/192/160 与原生相比误差几乎不变，说明信息瓶颈不在图像细节，而在别处。真正会掉点的是**目标只占几十像素**：手掌在 192 输入里 48 px 时，握拳的手指卷曲结构（几个像素）根本不可分，模型会把拳头读成张开的手。

所以：**框的大小是精度参数**。按 `框边长 = 实测目标像素 / 尺度中位数` 定，不要凭感觉给一个「看起来合适」的框。框太大导致目标太小，是被误诊成「模型退化」的常见原因。

## 7. 损失的尺度要和坐标的单位对齐

Wing loss 的 `w`/`eps` 是按像素级误差设计的，如果直接用在 0..1 归一化坐标上，`dL/dd = w/(d+eps)` 在整个误差范围内只从 5.0 变到 4.0，几乎没有形状（Adam 还会把常数因子归一化掉）。要么把坐标换成像素单位，要么按坐标尺度重设 `w`。同理，任何「稳健损失」先检查它的转折点落在你的误差量级上。

## 8. 数据增强的陷阱

旋转 + `clip(coords, 0, 1)` 会把转出画面的关键点拉回边界，制造错误标签。做增广前后必须各跑一次同样的评估；如果同时改了别的变量（比如热图 stride），得不出「增广没用」的结论。

## 9. 指标要拆开看，否则会被尾部支配

平均误差常常由最差 10% 的样本贡献 37%~38%。评估输出至少给：`mean / median / p90 / 崩溃率 / 分桶误差`。分桶方式：

- 按目标尺寸分位（小目标通常最差）；
- 按姿态/开合度分位（用「指尖到腕的平均距离 / 掌长」当开合度代理，取四分位）；
- 按关节分组（确认「某部分没学会」是不是真的——实测手掌关节只比指尖差 11%，而观感上像是差一倍）。

**当肉眼抱怨和分桶数据冲突时，先问清是哪一类问题（偏移 / 跳动 / 塌陷），不要立刻重录数据。**

## 10. 蒸馏的目标是「像教师」，不是「像真值」

如果上板是为了替代某个 PC 侧教师模型，评估指标就应该是「与教师的一致性」，而不是绝对精度——教师自身有噪声上限。想确认门槛是否可达，最便宜的办法是测**教师自身的自一致性**（同一图跑两次 / 两种模式各跑一次）。教师都不自洽的地方，学生不可能稳定。
