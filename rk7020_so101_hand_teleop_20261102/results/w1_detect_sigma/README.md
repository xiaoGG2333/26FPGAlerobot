# 高斯热图 sigma 实验：1.0 → 2.0（2026-10-15）

**一句话结论**：sigma=2.0 的**官方指标看着更好（4.44px vs 4.997px），但那是假象**——
conf 头整体变保守、25% 的正样本被排除（n=425 vs 539），**同召回率下定位反而更差**（4.81 vs 5.19px）。
**不采纳，冻结模型保持 run-5（sigma=1.0）不变。** 这次实验的最大价值是暴露了官方指标的口径陷阱（见 §4）。

## 1. 动机

热图回归里，监督目标宽度应与标签不确定度尺度匹配。本任务：
- 热图网格 = stride-4 的 36×36，1 格 = 4px（144px 尺度）
- 而 HaGRID 的 bbox 标注噪声实测 **8~11px**（近重复帧实验：同 user 近重复帧 GT 中心差中位 11.39px）
- 即 sigma=1.0 格(=4px) 比标签噪声还紧 —— 典型假设是"太紧的目标在噪声标签上会被强行平均、定位变钝"，故试 sigma=2.0 格(=8px) 对齐噪声尺度

## 2. 配置（单变量）

| 项 | 值 |
|---|---|
| 与 run-5 差异 | **仅** `--hm-sigma 1.0 → 2.0` |
| 其余 | 40 epoch / batch 64 / lr 3e-3 / workers 2 / hm_weight 1.0 / neg_extra 5 / cache256 / 从零训练 |
| 训练用时 | 8.5 min |
| best val median（train.py 内部口径） | **4.44px @ ep22**（n=538）；ep40 4.81px（n=538） |

## 3. 结果：官方指标 vs 同召回率（决定性对比）

### 3.1 官方指标（`detect/eval.py`，阈值 0.5，只统计被接受的正样本）
| 模型 | median | p90 | **n（接受数）** | 召回 | jitter |
|---|---|---|---|---|---|
| 旧版 run-5（sigma 1.0） | 4.997px | 52.58 | **539** | 95.6% | 4.717px |
| 新版（sigma 2.0） | **4.440px** | 60.13 | **425** | **75.4%** | 5.048px |

只看这一行会得出"提升 0.56px"的结论 —— **是假的**：新版把 114 个正样本拒掉了，剩下的当然是"好做的题"。

### 3.2 阈值扫描 / 同召回率（`eval_oob.py`，窗口内 537 个正样本）
| 阈值 | 旧版召回 | 旧版窗口内中位 | 旧版 ≤8px | 新版召回 | 新版窗口内中位 | 新版 ≤8px |
|---|---|---|---|---|---|---|
| 0.1 | **99.6%** | **4.81px** | **64.3%** | 96.1% | 5.19px | 59.5% |
| 0.2 | 98.5% | 4.76px | 64.6% | 92.0% | 4.88px | 60.3% |
| 0.5 | 95.7% | 4.59px | 65.4% | 75.8% | 4.23px | 66.6% |
| 0.9 | 81.2% | 4.20px | 69.5% | 48.2% | 3.59px | 74.9% |

**同召回率插值对比**（这是公平口径）：
- 召回 ~96%：旧版 **4.81px / ≤8px 64.3%** vs 新版 5.19px / 59.5% → 旧版好
- 召回 ~76%：旧版 4.20px（t=0.9，召回 81.2%）vs 新版 4.23px（召回 75.8%）→ 打平（新版还多拒了 5% 的样本）

→ **sigma=2.0 在同等召回下定位更差约 0.4~0.5px**，假设被否：更宽的高斯目标让 soft-argmax 的期望更"糊"，
峰值信息被平滑掉；而它带来的唯一变化是 **conf 头整体信心下降**（窗口外 conf 中位 0.9956 → 0.9084，
窗口内也普遍下降）—— 这恰好让"只看被接受样本"的指标变好看。

## 4. ⚠️ 方法论陷阱（本轮最重要的产出）

**`detect/eval.py` 的 median 是"被接受正样本的中位误差"，它同时受模型定位能力和 conf 阈值/信心水平支配。**
任何"让 conf 变保守"的改动（加负样本、改热图宽度、换阈值）都会自动排除难样本、把 median 做好看，
而 `n` 只是顺带打印出来的一个数字。本次两个实验都踩在这个陷阱上：
- 窗口外负样本版：median 4.07px @ n=452（召回 80.1%）
- sigma=2.0 版：median 4.44px @ n=425（召回 75.4%）

**以后对比检测精度必须同时报**（或至少报匹配召回下的值）：
1. **召回**（被接受数 n / 正样本总数）
2. **同召回下的中位/p90/≤8px 占比**（`results/w1_detect_oob/eval_oob.py` 已实现阈值扫描）

建议把这条写进《网络结构清单》的验收口径（已在 v1.3 记为已知限制 11）。

## 5. 判定

| 目标 | 结果 |
|---|---|
| 同召回下定位更准 | ❌ **未达成**（96% 召回时 5.19px vs 旧版 4.81px） |
| 官方 median 更好 | ⚠️ 表面成立（4.44 vs 4.997px）但为选择效应，不作为依据 |
| 抖动 ≤8px | ✅ 5.05px |
| 域内误触发 0% | 未单独复测（该版不采纳） |

**决定**：不替换冻结模型；sigma 保持 1.0 格。**并且确认"用更宽的高斯目标去迁就标签噪声"在本模型上无效**——
soft-argmax 的精度来自峰值形状，平滑它反而伤了定位。这条已记入 LEDGER 避免重复尝试。

```bash
cd model && export HAGRID_ROOT=data/cache256
python detect/train.py --epochs 40 --workers 2 --hm-weight 1.0 --hm-sigma 2.0 \
    --neg-extra-weight 5 --out ../results/w1_detect_sigma/_hm2.pt

    --eval-out ../results/w1_detect_sigma/detect_eval_sigma2.json

    ../results/w1_detect_sigma/_hm2.pt --tags 旧版 新版 --tag sigma2
```
