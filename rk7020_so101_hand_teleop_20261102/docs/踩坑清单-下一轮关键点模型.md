## 0. 最高优先（本轮代价最大的 4 条）

- ★**不要**只看"被接受样本的中位数"就宣布精度提升。`model/detect/eval.py` 只在 `pred_conf>0.5` 的样本上算 median/p90，且把 `n` 报成"接受数"。任何让 conf 头变保守的改动（加负样本、换热图 sigma、改尺度增强）都会自动丢掉难样本，让中位数虚假变好。**必须同时报召回 + 同召回下的误差**，否则结论无效。
- ★**不要**用单点阈值比较新旧模型。conf 阈值是部署端自由旋钮，要扫 t=0.1…0.9 出曲线（本项目的 OOB / sigma2.0 / zoom0.60 / QAT 四个实验，全都是"官方中位数变好、匹配召回后不成立"）。
- ★**不要**跨口径比较准确率。93.09%(2类/原图/889 val) 与 92.00%(3类/cache256/1000 val) 不可比；**同一份权重**在原图 90.07% vs cache256 90.07→ 差约 3pt 就是图像源造成的。
- ★**不要**在需求未经书面确认时"顺手"开工。计划批准 ≠ 授权开工；结构清单变更、把 no_gesture 改判为正样本这类事必须先签字。

## A. 评测口径

- **不要**把 `jitter<=8px` 当成整体通过。曾出现 median 25.81px 惨败而 jitter 2.58px 通过；验收必须 median 与 jitter **各自**达标（该口径已由主人 2026-10-14 明确）。
- **不要**在训练未真正结束时跑 eval。曾用 epoch-34 的中间检查点评过一次分，结论全废。
- **不要**忘了 eval 的 `n` 是"conf 接受数"而非正样本总数（564 正样本里可能只接受 425~543 个，横向比较前先对齐 n 或看召回）。
- **不要**用 val 集做量化校准、又用同一个 val 报精度，却不注明乐观偏差。文档里必须写明"校准集=val，精度偏乐观"。
- **不要**忽略标注噪声天花板。同用户近重复对的 GT 中心相差中位 **11.39px**（≈ 验收阈值 8px），且**训练误差并不比验证小**（4.76px vs 5.02px）→ 8~40px 的误差带是 HaGRID 标注抖动下限，调参调不穿。
- **不要**只看总准确率。分类器必须报 per-class recall + 混淆矩阵 + **"其他类误动率"**（安全指标）。92% 总精度掩盖了 OK 39.1%、剪刀 37.9% 被判"张开"。
- **不要**在没登记验收门槛的情况下先看结果再挑指标。门槛要在开跑前写好（本项目 OOB 那轮就是这么做的，虽然后来失败了，但结论可信）。
- **不要**用重建的指标脚本替代官方 eval 来"图省事"——口径一定会分叉。正确做法是给官方脚本加开关（如 `--int8`），保证 float/int8 用同一套指标定义。
- **不要**把 val 上做过模型选择的结果当成泛化精度汇报。

## B. 模型/数据设计

- ★**不要**用 `GAP + 单个 1x1 conv` 做坐标回归。全卷积末端全局平均池化后单点输出，会让**每个空间位置输出同一个 (conf,u,v)**，空间分辨率为零 —— 这是 D1 换成 soft-argmax 的根因（换头前 median 25.81px，换后 4.44px）。关键点模型同理：21 个点必须逐点有空间定位能力。
- **不要**只信 docstring 的分辨率描述。DetectNet 注释写"9x9 最终特征图"，实测是 18x18；用 `dump_layers.py` 实测。
- **不要**让 softmax 温度无约束变动，也不要误读热图。本模型学到的 `beta≈3.71`，热图是**弥散**的（峰值概率 0.041、熵 8.43/10.34 bit），既不是 one-hot 也不能当尺寸/置信度信号用。
- ★**不要**忘了 `return_hm=True` 返回的是**热图 logits，不是概率**。我因此算出"热图扩散=0、退化成 one-hot"的错误结论并差一点汇报出去；必须显式 `softmax` 后再做统计。
- ★**不要**在没核对输入语义/单位/是否退化前相信自己的相关系数。我本轮两次差点报错误结论（一次漏 softmax，一次把退化 ROI 当成自适应）。
- **不要**以为负样本"加进池子"就等于"训练用到了"。`neg_pool` 是"先 HaGRID、后自录"的顺序，每轮只取前 `int(len(pos)*neg_ratio)` 条 → 自录负样本**永远抽不到**，一次 40 轮训练完全白跑。修法：构造后 `random.Random(seed).shuffle`，并**每轮验证实际抽到多少条**。
- **不要**低估负样本语义冲突。HaGRID `no_gesture` 官方定义是"第二只自然放置的手"，里面**有手**；拿它当"无手"负样本与检测器"手在不在"的语义冲突（残留 17.8% 误触发）。
- **不要**指望输出端后处理能救训练时没见过的失败模式。entropy / 时域一致性 / 边界检查对"手在窗外"全部无效（那些样本热图反而更尖锐）；要治就治数据侧。
- ★**不要**让训练几何与部署几何不一致。训练曾用"近满幅非方窗(192x144)竖向压 25%"，评测用"短边缩到 144 + 中心裁 144x144"，同一物体在 val 里大约 1.33 倍 → 系统性域偏移。裁窗策略必须与部署端逐字一致。
- **不要**把"手在窗外"当可学习的边界问题：val 里 45% 的 OOB 样本 GT 中心只出框约 7.5px，低于 8~11px 标注噪声；且部署端中心裁天然会切掉边缘。正确处置是改视野（letterbox / 放大 ROI / 尺寸自适应），不是加负样本。
- ★**不要**只做 zoom-in 就说"做了多尺度增强"。`k` 被 `clamp(8, min(k, nh, nw, size))` 且短边已缩到 `size`，`k` 永远不超过 `size` → 只有放大没有缩小（zoom_min 0.88 实际只覆盖 1.00~1.13x）。
- **不要**忘了 ROI 尺度是分类器的主要失效源。**固定 0.35×短边** 的 ROI 在"手离镜头近"时会裁进手内部，握拳只剩一片平皮肤 → 判"张开"（握拳召回 38.7%）；放大到 0.59/满幅 → 88.7%/91.9%。关键点模型时代同样要解决"ROI/视野尺度"问题。
- **不要**假设数据集是均质的。HaGRID 子集采样到 **88 种源分辨率**（360x640 / 1080x1920 / 1920x1440 / 1920x1920 / 1425x1488…），纵横比差异直接决定裁窗行为（竖图是竖向出框、横图是横向出框）。
- **不要**信文件名当标签。曾录到 `L1_open_light.mp4`（名字像"张开"，实际是**实验室空镜**）、`S2_arm_only.mp4.mp4`（双扩展名）；用文件名定标签会把数据搞脏。

## C. 训练流程与并发

- ★**不要**假设"已被杀掉的训练真的死了"。旧进程（PID 39472 + 4 个 worker）与新进程写同一个 `--out`，反复覆盖对方的最优权重，**所有评测被污染**。启动前务必用 `Get-CimInstance Win32_Process`（Windows 上 `wmic` 返回空）核对 PID，`taskkill //T //F //PID` 杀整棵树。
- **不要**让两个训练共享同一个 `--out` 或 log 路径。
- **不要**在训练运行时改 `dataset.py` / `transforms.py`（会污染正在跑的进程）。
- **不要**用全零/全体样本训练完就发结论；先跑 1 epoch 冒烟测试（本轮 1-epoch 冒烟测出了 `gauss_target` 的维度 bug）。
- **不要**忽略"conf 头一旦变保守就冻结约 20% 的画面"——这在下游是实打实的失效，必须一起报。
- **不要**忘了留基线：覆盖 `model/frozen/*.pt` 前，先把旧权重+history+eval 归档到 `results/<轮次>/<run>/`（本项目每次覆盖前都归档过）。

## D. 量化 / INT8（下一轮仍要走这条路）

- ★**不要**给已经量化的张量再做一次 round-trip 量化。`qfake._ste` 里 `_dequant(_quantize(x))` 双重量化 → QAT 数值全崩（5.18px → 38.63px，loss 1.5~2.6）。正确写法 `dq = _dequant(x, s, zp)`。
- **不要**以为 `round/clamp` 的假量化有梯度——它几乎处处导数为 0，QAT 必须显式写 STE。
- **不要**把 affine 的 `zp` 按 uint8 约定算完再 clamp 到 int8：正确是 `zp = round(-lo/s) - 128`（否则 ReLU 型激活的表示区间被砍半，SNR 8.96dB vs 54dB）。
- **不要**用"码值贴边界"当 clip 比例（zeros 会被误报成 ~90% 裁剪）；要统计**落在 [lo,hi] 之外的值**比例。
- **不要**让校准的 `randperm` 不设种子（scale 每次漂 ~0.2pt，结果不可复现）。
- **不要**用"输入 scale"去量化 softargmax 热图输出层，必须单独做 OUTPUT 校准。
- ★**不要**把 softmax/soft-argmax 一起量化。ORT 全算子 QDQ 让检测退化到 9.673px（**不达标**），只量化 conv 是 5.237px（达标）。结论：**热图交 int8，softmax/sigmoid/期望坐标保持浮点**。
- **不要**忘了 BN 折叠后比较要拿"同样折叠过的 float 网"当参考（否则差一个 BN scale，层 SNR 全负）。
- **不要**忘了 per-channel 权重也要查"压成 0 的比例"和通道内动态范围（最大 325x）。
- **不要**期望固定 scale 的 QAT 能补回精度：实测 15 epoch 固定 scale QAT = 5.48px，与 PTQ 5.495px 一样，**一点没补回来**。
- **不要**在报告里把"分类器 INT8 后 fist recall 88.4~88.8%"当成过门槛（自设门槛 90%，它反而挂了）。

## E. 工程脚本 / 工具链

- ★**不要**用 `python - << 'EOF'` 跑长脚本（约 9KB 就被截断，报 "here-document delimited by end-of-file"）。写到 `_scratch/xxx.py` 再执行。
- ★**不要**用"带 assert 的多步脚本"改代码。前面步骤已成功、后面断言失败 → **整个文件不写盘**，但你已看到"成功"的打印（`--zoom-min` 的 `add_argument` 就这么静默丢了，启动才报 unrecognized arguments）。每个文件的编辑要单独写盘。
- ★**不要**用"两个锚点之间的整段替换"（会连带删掉区间里的函数：`load_jpeg_oob` 就这么被删过）。

- **不要**用相对 `--out` 还不确认 cwd：`cd model/classify` 后 `../results` 落到 `model/results`，四个产物全跑错地方。
- **不要**对用户传入的相对路径直接 `relative_to(ROOT)`（ValueError）；先 `resolve()` 或 try/except。
- **不要**直接 json.dump numpy 标量（`int64 is not JSON serializable`），先 `int()/float()`。
- **不要**在 f-string 表达式里放反斜杠转义引号（SyntaxError，Python 3.10）；先算到变量里。
- **不要**把 git-bash 的 `/d/...` 路径交给 python 参数或重定向（FileNotFoundError）；统一用 `D:/C_O_D_E/...` 或相对路径。

## F. 关键点模型专项（下一轮直接相关）

- **不要**忽略**多只手**：HaGRID 部分图有 2 只手且**两只都有 21 点标注**（2026-10-16 抽样：fist 2/13、palm 3/12、like 3/13、ok 3/12、peace 0/15、no_gesture 2/13 张是 2 手；第二只手常出现在画面下方/胸腰处）。必须先定义"**回归哪只手**"（用 `united_label`/目标手 bbox 的顺序取那只），否则第二只手就是纯噪声。数据条目数≠手数（159,615 条 = 123,616 单手 + 35,999 双手）。
- **不要**忘了 landmarks 会**出界**：抽样坐标 x∈(0.068, 0.869)、y∈(0.054, **1.034**)，`ok` 与 `no_gesture` 的 y 超过 1.0。裁窗后部分点会落到窗外（同 K 节那条）。
- **不要**忘了 HaGRID 里手只占画面很小（bbox 面积中位 0.0187 ≈ 线性 14%），而 RPS 里手占短边 **89%** —— **6 倍尺度差**。关键点模型必须直面尺度：训练做尺度增强（注意 k 不能超过 size 的既有坑）/ 部署端做尺寸自适应，否则重蹈"单个冻结模型跨不过域"的覆辙。
- **不要**跳过形态标准检查：已确认 HaGRID 的 21 点是 MediaPipe 顺序（0=手腕，1-4 拇指，5-8 食指，9-12 中指，13-16 无名指，17-20 小指），且是**归一化 [0,1]**（不是像素）；参照 `results/w3_keypoints/samples_landmarks.png`。
- **不要**把"单点 (u,v)+conf"的范式直接搬来当关键点：需要 **21 通道热图**（建议挂在 s4 的 36x36 上、每点 soft-argmax），约 +1.8M MACs（检测 21.06M→约 23M，合计约 27.6M，仍在 A9 30M 预算内）。
- **不要**忘了**手腕点是独立语义点**，HaGRID 的 bbox 中心不是手腕；要从中指 MCP / 掌根 landmarks 推导，并检查遮挡/越界。
- ★**不要**让关键点标签因为裁窗而出界——出框会同时污染 21 个点（本项目单点都出现过 4.8% 出框、误差中位 106px）。训练裁窗必须含手（`keep_center=True`）或用更大视野。
- **不要**给角度用普通 L1/MSE：角度有周期性，-179° 与 +179° 会被当成差 358°。用周期损失（sin/cos 双通道或 1-cos(Δθ)），并明确单位与范围。
- **不要**忽视**左右手与镜像**：旋转/翻转的符号依赖左右手，先查 annotations 里 `meta`/`handedness` 是否给了，没给就要自己定义并保证一致。
- **不要**只报 PCK 均值：要分层报"手占画面比例（远/近）× 画面位置（中心/边缘）"的误差，因为部署端真正关心的是这两条轴（本项目小手的误差明显更大、边缘会被裁掉）。
- **不要**忘了关键点也解决不了 Z（单目尺寸推深度已在计划书里明确弃用）。
- **不要**忘了"其他手势"的安全语义：张开/闭合之外的（大拇指/OK/剪刀/指向）必须"夹爪不动"。关键点+伸指数规则能帮（open=5 / OK=3 / 剪刀=2），但**必须按"其他"类样本单独评其他手势误动率**，不能用总准确率糊过去。
- **不要**在 144px 输入上训完就直接用于 640x480 摄像头：部署裁窗/缩放必须与训练一致（本项目吃过一次 1.33x 的系统性偏差）。
- **不要**忘了结构清单变更需要签字，且 MAC 预算是硬约束（A9 ≤30M / PL ≤60M @256x256 等效；A9 15fps、PL 30fps）。
- **不要**忘了 INT8 路线：21 通道热图**输出层单独 OUTPUT 校准**，softmax/期望坐标保持浮点（否则 9.67px 的教训重演）。
- **不要**忘了先登记验收门槛再开跑，且门槛**必须包含召回**。

## G. 环境与硬约束（本机）

### G0. 板子变更：Zynq7020 → **Zynq-7100（XC7Z100）**（主人 2026-10-16 通知，资源充足）

| | Z-7020 | **Z-7100** | 倍数 |
|---|---|---|---|
| Logic Cells / LUT / FF | 85K / 53.2K / 106.4K | **444K / 277.4K / 554.8K** | 5.2x |
| DSP48E1 | 220 | **2020** | 9.2x |
| Block RAM | 4.9Mb (140) | **26.5Mb (755)** | 5.4x |
| PL 工艺 | Artix-7 | **Kintex-7**（-2/-3 可达 ~250MHz） | |
| PS (Cortex-A9 ×2) | 最高 866MHz | 最高 **1GHz**（**同一微架构，无 int8 dot 指令**） | 1.15x |
| L2 Cache | 512KB | 512KB | 1x |

（来源：AMD Zynq-7000 Product Selection Guide / UG585。数据 2026-10-16 核实）

- **不要**以为“换了板子” = “CPU 变快”：**PS 几乎没变强（A9 同架构，只多约 15% 频率），PL 强了 5~9 倍**。所以后处理**不要放 PS**，要放 PL（HLS）——否则白白浪费这次换板。
- **不要**担心后处理算术量：关键点方案的后处理合计约 16~28 万操作/帧（21×36×36 热图 = 27,216 格 × 6 ops 的质心 + 约 150 个几何运算），PL@150MHz 并行后 **<0.1ms**，A9 标量也只要 0.05~0.2ms（33ms 帧周期的 0.3~0.6%）。
- ★**不要**把 softmax 的 exp 放到 ARM 上用 libm 跑：21×1296 = **27,216 次 expf**，每次 50~200 周期 → 1.4M~5.4M 周期 = **1.4~5.4ms**（纯串行、还可能cache 抖动）。用**归一化 relu 质心**（`w=max(0,h); p=w/Σw`）替代，零 exp；或用 PL 里的 exp LUT（512B BRAM，2~3 周期/格）。
- **不要**让热图走 DDR：21×36×36 int8 = **27KB**，26.5Mb BRAM 装得下全部热图；PS 只需收 21×2 坐标（84B/帧）。一帧**一次**搬运，不要几百次小 DMA/中断（字节数不是问题，次数才是）。
- **不要**把后处理串在关键路径上：整链是“曝光+读出 33ms → CNN 0.3~3ms → 后处理 <0.2ms → IK+串口 0.1~1ms”，后处理只是零头；真正的延迟大头是相机帧周期与舵机总线（6 舵机 SYNC_WRITE @1Mbps ≈ 0.5~1ms）。用 ping-pong 双缓冲 + 流水线。
- **不要**靠提高热图分辨率换角度精度：36×36 保持不变；精度靠“裁小手再放大 ROI”拿（输入张量尺寸不变 → **MAC 不变**，只是裁得更紧）。72×72 是 4 倍后处理成本，144×144 是 16 倍，没必要。
- 结构清单 v1.3 里的 “A9 ≤30M / PL ≤60M MAC” 预算是为 7020 定的；换 7100 后按数值上已宽松约 10 倍，但**预算数字要不要改需主人拍板**（不改也不会超）。
- **不要**忘了 HaGRID v2 标注里**没有左右手标签**：`meta` 只有 `age/gender/race`，`united_label=None`。要训“左右手”必须先拿到标签（MediaPipe 伪标注，或主人自录 1~2 分钟已知左右手视频；后者同时是部署域数据，价值更高）。
- **不要**用系统 Python（`C:\Python310`）；本项目环境是 `D:\Anaconda3\envs\fpga_amd-pi\python.exe`（torch 2.11.0+cu128，RTX 5060 Laptop）。
- **不要**忘了 `python3` 是 Microsoft Store 假桩（无输出、退出码 0）；脚本一律用 `python`。
- **不要**忘了 conda 可执行文件是 `D:\Anaconda3\_conda.exe`，且需 `CONDA_ENVS_PATH=D:\Anaconda3\envs`（否则装到 C:，C: 只剩约 23G）；环境名必须以 `-pi` 结尾。
- **不要**指望 ncnn / onnxsim / onnxscript 已安装（都没有）；`torch.onnx.export` 要用 `dynamo=False`，且必须加 `dynamic_axes`（否则导出的是 batch=1 静态图，ORT 校准报 "Got: 32 Expected: 1"）。
- **不要**忘了网络现实：github.com / huggingface.co 直连不通（需 VPN），可用 `codeload.github.com`、`hf-mirror.com`、Gitee、ModelScope、`zenodo.org`、`download.tensorflow.org`、PyPI(清华镜像)；Kaggle 无 token、Roboflow 403、platform.ultralytics.com 需 key。
- **不要**把 GUI 程序只在 `--no-window` 下自检。本项目因此漏掉 headless OpenCV 的 `cv2.imshow` 崩溃（`opencv-python-headless` → 必须装 `opencv-python`），最后是主人在实测时才炸。GUI 程序必须真开窗自检；后台跑 GUI 要 `python -u`，否则 log 是空的。
- **不要**忘了 `HAGRID_ROOT` 相关的另一条：**dataset.json 一改就必须重跑 `model/data/build_cache.py`**（否则 3 类训练直接 ValueError 读不到 peace 的缓存图）。
