## 2. 输入输出契约（与部署一致）

### 检测网
| 项 | 规格 |
|---|---|
| 输入 | **1×3×144×144**，RGB，`x/255` 后按 ImageNet mean/std 归一化（`(x-mean)/std`，mean=[0.485,0.456,0.406]，std=[0.229,0.224,0.225]） |
| 预处理（部署必须一致） | 原帧**短边缩放到 144** → **中心裁剪 144×144** → 归一化 |
| 输出 | `conf`（sigmoid，0~1）、`u,v`（归一化 0~1，144×144 尺度上的手掌中心） |
| 映射回原帧 | `x_px = u × W_frame`、`y_px = v × H_frame`（缩放+裁剪的逆变换） |
| 结构特性 | 全卷积、静态 shape、无 NMS、无动态控制流；conf 头 = GAP+1×1；u/v 头 = stride-4(36×36) 热图 + soft-argmax |

### 分类网
| 项 | 规格 |
|---|---|
| 输入 | **1×3×80×80**，RGB，同一套归一化 |
| 预处理 | 用检测框按 **1.3~1.8× 扩展**裁 ROI（`expand=1.5` 为默认）→ resize 80×80 |
| 输出 | **3 logits**（0=`fist` 五指闭合 / 1=`palm` 五指张开 / 2=`other` 其它一切 → 夹爪不动）；“其它”含竖拇指、OK、剪刀手、自然搭手、无手背景 |
| 结构特性 | 全卷积 + GAP + 1×1（无 FC 大矩阵乘） |

## 5. 量化方式（INT8，目标：A9 版 NCNN / PL 版 HLS 同一套参数）

| 项 | 方案 | 说明 |
|---|---|---|
| 权重 | **INT8，逐输出通道对称量化**（per-channel symmetric，scale = max\|w\|/127） | 深度卷积对逐通道量化敏感，必须 per-channel |
| 激活 | **INT8，逐张量非对称/对称**（校准集 = 检测 val 正样本 564 张 + 分类 val 1000 张的 min-max，取 99.9 分位去离群） | ReLU 后天然非负，可用 uint8 非对称 |
| BN | **推理时折叠进前一层 conv**（`conv_bn_relu` 已按此设计，无独立 BN 算子） | 逐层表中 BN 行的 MACs=0 即此意 |
| ReLU | 量化 ReLU（clip 到 [0, 127]） | 白名单内 |
| 残差/Concat | 无 | 结构里没有，省掉跨层 scale 对齐 |
| 1×1 conv / depthwise | 均走同一套量化；depthwise 走 per-channel | HLS 侧可复用同一引擎（g=N） |
| **softmax / soft-argmax** | **不量化进引擎**：热图输出（36×36 int8）交给后端算 softmax+期望 | 需要 exp(1296)。**实测：这一条是必需的**——第三方量化器把这段算术也量化后，检测中位 5.24 → **9.67 px（不过关）**；若无 exp 单元，可换 `w=relu(h); p=w/Σw` 的归一化 ReLU 质心（精度仍未测） |
| conf sigmoid | 同上，后端算；A9 版直接浮点 1 次 | 只有 1 个标量，代价可忽略 |
| 首层 | 输入 int8（uint8 减 mean），conv 3×3 s2 | 无特殊处理 |
| 量化工具 | PyTorch QAT（可选）→ ONNX → onnxslim → NCNN int8（A9）；HLS 侧用同一 scale 表 | 见 §5.1 实测 |

### 5.1 INT8 实测结果（2026-10-15，红线 3 遗留项闭环）

两种独立实现：① `model/common/qfake.py` 自写 PTQ 假量化模拟器（产 §5.2 的 scale 表）；
② onnxruntime 官方静态 QDQ 量化（per-channel、MinMax）做交叉验证。校准集 = 全 val（检测 982 / 分类 1000 张），分位 99.9%。

| 模型 | 方案 | 关键指标 | 与 float32 之差 | 判定 |
|---|---|---|---|---|
| 检测 144×144 | float32 | 中位 4.997 px / 抖动 4.717 px / 域内误触发 0% | — | ✅ |
| 检测 | 模拟器 `affine` | 中位 5.064 / 抖动 4.695 / 误触发 0% | +0.07 / −0.02 px | ✅ |
| 检测 | 模拟器 `sym` | 中位 5.495 / 抖动 4.704 / 误触发 0% | +0.50 / −0.01 px | ✅ |
| 检测 | ORT 只量化 Conv | 中位 **5.237** / 抖动 4.969 / 误触发 0% | +0.24 / +0.25 px | ✅ |
| 检测 | ORT 量化全部算子 | 中位 **9.673** / 抖动 5.572 | +4.68 px | ❌ **故 softmax+期望必须留浮点** |
| 分类 80×80 | float32 | acc 92.00% / fist recall 90.35% / 其它误动作 7.11% | — | ✅ |
| 分类 | 模拟器 `affine` | acc 91.10% / 88.80% / 6.65% | −0.90 pt | ⚠️ |
| 分类 | 模拟器 `sym` | acc 90.80% / 88.42% / 7.57% | −1.20 pt | ⚠️ |
| 分类 | ORT 全部算子 | acc 91.30% / 89.58% / 7.57% | −0.70 pt | ⚠️ |

**QAT 实测（2026-10-15）**：`detect/train.py --qat-from frozen/detect_fp32.pt --qat-mode sym`（折叠 BN + val 校准 + STE 假量化，15 epoch / lr 3e-4）best **5.48px**，对比 PTQ **5.495px** —— **固定 scale 的 QAT 无收益**（瓶颈在激活逐张量量化与标签噪声，不在权重）；要再抠需每 N epoch 重校准激活 scale，上限约 0.3~0.4px，性价比低故未做。详见 `results/w1_detect_oob/README.md` §6。

- **结论**：检测 int8 可直接用（代价 ≤0.5 px，两门槛仍过）；分类 int8 掉 0.7~1.2 pt、闭合方向 recall 到 88~89.6%，若要守 ≥90% 需 QAT 或混合精度
- 权重体积：检测 27.9K 参数 ≈ **28 KB** int8（fp32 140 KB）；分类 15.7K ≈ **16 KB**（fp32 82 KB）
- 逐层误差预算：输入量化 SNR **16.2~45.8 dB**、输出 SNR **10.7~40 dB**、输出余弦 0.96~1.0；权重被压成 0 ≤1.04%
- BN 折叠正确性校验：折叠前后输出最大绝对差 6.3e-07（检测）/ 2.0e-06（分类）
- 证据与坑：`results/w1_int8/README.md`（含"affine zp 约定写错""逐层 SNR 基准必须同样折叠 BN""ORT 会量化 softmax"三条踩坑记录）

## 7. 为什么改检测头（一行结论 + 证据）

- 旧结构（GAP + 1×1 三通道线性头）val 中位误差 **25.81 px**（画面 18%），**96 维 GAP 特征线性探针天花板 26.9 px** → 结构天生不能定位，非训练问题。
- 改为 stride-4 热图 + soft-argmax 后：中位 **4.41 px**、抖动 **4.52 px**，均过 8 px 门槛。
- 完整证据链：`results/w1_detect_train/README.md` §4–§6。

## 8. 已知限制（冻结不等于完美，必须随清单一起交接）

1. **HaGRID 标注噪声 ≈ 门槛本身**：近同帧（画面差异 0.2%）配对的标注中心中位跳 **11.4 px**，70% 的对 >8 px → HaGRID 上 ≤8 px 门槛的测量已触数据天花板（`results/w1_detect_train/detect_label_noise.json`）。
2. **val 上只有 62% 样本 ≤8 px**：p90 = 55.4 px。其中 4.8% 是"手不在部署裁剪窗口内"（拍摄取景问题，非模型），其余主要是标注噪声。
3. **真实验收必须在自录演示数据上重做**：`model/data/recorded/` 至今为空（计划书本来就把自录数据定为最终判据）。
11. **验收口径必须带召回**（2026-10-15 新增，重要）：官方 median 只统计"被接受的正样本"，任何让 conf 变保守的改动都会自动丢掉难样本、把 median 做好看。实测例：hm_sigma=2.0 的官方 median 4.440px 看着优于 4.997px，但其接受数从 539 掉到 425（召回 95.6%→75.4%），同召回口径下反而差 0.4~0.5px。**以后报检测精度必须同时给"召回 + 同召回下的中位/p90/≤8px"**（工具：`results/w1_detect_oob/eval_oob.py`）。
12. **"手在窗口外"不能靠训练拒识**（2026-10-15 实测）：val 正样本中 4.8%（27/564）的标注中心落在部署中心裁剪窗口之外，旧模型在其上 conf 中位 0.9956、误差中位 106px。加入 1820 条"目标手在窗口外"负样本重训后，拒识率只到 **25.9%**（目标 ≥90%），分层分析显示拒识率与"离边界多远"不单调、且离边界 20px+ 的窗口内样本误拒 19.1% —— 模型只是整体压低了 conf，**没学到边界**。根因：该组真值**中位只离边界 7.5px < 8~11px 标注噪声**，判据在 HaGRID 上物理不可学。→ 该失败模式应由**取景（letterbox / 更大裁剪比，需重训）或时序门（连续 K 帧一致，0 MACs）**解决。详见 `results/w1_detect_oob/README.md`。
4. ~~INT8 未实测~~ → **已实测（2026-10-15）**：检测 int8 中位 5.24~5.50 px / 抖动 4.70~4.97 px（门槛 8px，仍过）、域内误触发仍 0%；分类 int8 acc 90.8~91.3%（−0.7~1.2 pt）、闭合 recall 88~89.6%（浮点 90.35%）。**softmax+空间期望必须留浮点**（全量化会让检测中位崩到 9.67 px）。分类要守 ≥90% 需 QAT。详见 §5.1。
5. **conf 头不区分成败**：失败样本 conf 中位 0.991（成功 0.9975）→ 闭环需另加自检（如热图熵/时序一致性），不能只信 conf。
6. softmax 的 exp 对 HLS/PL 是新算子，需评估资源或切后备方案。
7. **域内误触发已清零，但仅覆盖 93 帧自录素材**（1 个工位、2 种光照）：检测网在主人实验室空镜/机械臂上的 conf 从 0.926 降到 ≤0.057（`results/w1_detect_neg/`）。若演示机位或光照变化大，需补录负样本。
8. **三分类的“其它”仍有 7.11% 误动作**：集中在 OK（39.1%）与剪刀手（37.9%）—— 手形离“五指张开”太近，300 张/类不够。背景/机械臂/自然搭手几乎不误动作（0% / 2.8%）。缓解：扩样到 1200+/类，或闭环加“连续 K 帧一致才动作”的时序兜底（零 MACs）。
9. **图源口径未统一**：旧二分类的 93.09% 是“原图裁 ROI”结果，同一权重在 256px 缓存口径下只有 90.07%（`results/w2_classify_3cls/eval_2cls_on_other.json`）。部署 ROI 来自相机原帧（约 100–200px），更接近缓存口径，建议后续统一并在 cache256 上重测。
10. **HaGRID `no_gesture` 语义冲突**：官方定义里它含“不做手势的手”，却一直当检测负样本（conf=0）用（实测仍有 17.8% 报警）。建议改为检测正样本 + 分类 other，需再训一轮确认。
