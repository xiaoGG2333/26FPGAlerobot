# 翻腕 vs 转腕：单目能不能分开？（2026-10-17）

> 起因：标定时找不到"只动翻腕、不动转腕"的姿势，`roll` 和 `pitch` 会一起动。

## 结论（一句话）

**手掌正对镜头时，"翻腕（旋前/旋后 σ）" 和 "画面内转腕（ψ）" 是绕同一根轴的同一个旋转 —— 相机光轴。
所以不存在能把它们分开的标定点，这不是标定问题，是几何退化。**

数值证据见下节。要分开只有三条路：**改姿势 / 改映射（只用 1 个旋转）/ 加硬件**。

---

## 1. 数值验证（`sw/axes_check.py`）

用简化手模型 + 与 `pose_map.py` 完全相同的几何（θ=atan2(p9−p0)、法线去旋后 φ/ψ、指轴 asin(x_z)），
对三种运动做中心差分求敏感度（单位：度/度，即"手转 1° 该特征动几度"）：

| 掌倾 | 运动 | θ 画面内 | φ 法线去旋 | ψ | asin(x_z)指轴 |
|---|---|---|---|---|---|
| **0°** | 翻腕 σ | **57.3** | 0.0 | 0.0 | 0.0 |
| 0° | 屈伸 β | 0.0 | 57.0 | 6.0 | 57.0 |
| 0° | 转画面 ψ | **57.3** | 0.0 | 0.0 | 0.0 |
| 45° | 翻腕 σ | 40.5 | 4.2 | **−40.3** | 4.2 |
| 45° | 屈伸 β | 0.0 | 57.0 | 6.0 | 57.0 |
| 45° | 转画面 ψ | 57.3 | 0.0 | **0.0** | 0.0 |
| 60° | 翻腕 σ | 28.7 | 5.2 | **−49.4** | 5.2 |
| 60° | 转画面 ψ | 57.3 | 0.0 | **0.0** | 0.0 |

读法：

- **掌倾 0°（掌正对镜头）**：翻腕和转画面在两个通道上的数字**完全相同**（57.3 / 0 / 0）→ 完全退化。
  前臂轴 ≈ 相机光轴，两者就是同一根轴。
- **掌倾 45°**：翻腕开始把能量分到 **ψ**（−40.3°/°），而转画面仍然只进 θ、ψ 为 0 → **ψ 是唯一能分开二者的量**。
  但 θ 通道仍然同时被两者驱动（40.5 vs 57.3，比值 0.71）→ 靠 θ 分不开，只能靠 ψ。
- **屈伸 β 一直很干净**：只进 φ（57.0）和指轴深度倾斜 asin(x_z)（57.0），完全不进 θ。**pitch 从来不是问题，roll 才是。**

顺带解释了以前的实测：φ 与 θ 相关系数 −0.46、φ 的 std 12.7° —— 那正是退化带来的串扰。

## 2. 三条出路

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A. 改姿势（斜掌）** | 掌面与镜头成 30–60°（手斜着拿，别正对），roll 取 **ψ**，pitch 取 **φ** | 两个旋转都来自手，直觉最贴近"手腕两自由度" | 手不能正对镜头；斜拿时位置映射要重采零位；ψ 在接近正面时仍会变噪声 |
| **B. 只用一个旋转 + 位置给 pitch**（推荐） | roll 取 **θ**（翻腕/转腕都当"转"），pitch 改由**掌心纵向位置 v** 驱动 | 完全避开退化；零标定歧义；符合 5 轴臂 + yaw 反算的既有设计（pitch 不再和工作空间抢那 1 维冗余） | pitch 不再是"真的腕俯仰"，是位置映射，手感偏摇杆 |
| C. 加硬件 | 腕部 IMU，或侧上方 45° 第二摄像头 | 一次性消除退化，最稳 | 要改硬件/双目标定 |

**为什么 B 不损失信息**：退化时"翻腕"和"转腕"对手臂来说是同一个动作，映射到 roll 都不算错；
真正缺的是第二个旋转自由度，而 5 轴臂本来就只有 5 个自由度 —— 用位置去补 pitch 比用不可观测的角度去补更稳。

## 3. 已实现（`sw/pose_map.py`，现场可切换，不用重启）

标定文件新增两个源开关，默认保持原行为：

```json
"roll":  {"source": "theta", ...}   // theta=画面内旋转(默认) | psi=法线出平面(方案A，需斜掌)
"pitch": {"source": "phi",   ...}   // phi=法线去旋后倾角(默认) | v=掌心纵向位置(方案B)
```

- CLI：`--roll-source theta|psi`、`--pitch-source phi|v`
- 现场热键：**`t`** 切 roll 源、**`u`** 切 pitch 源（切换时自动清平滑，并打印新源）
- 零位现在同时记录 `theta0 / phi0 / psi0 / u0 / v0`（用 `psi` 方案必须重新按 `c`）
- 面板 ③ 段实时显示当前源：`③ 标定 roll←psi pitch←v（t/u 换源 · c 采零位 · w 保存）`

## 4. 建议的现场对比流程

1. 正常坐姿，掌正对镜头 → `c` 采零位 → 手在本面内转（转腕）看 `roll` 是否跟、翻腕看 `pitch` 是否被错误带动 → **这就是主人遇到的现象**
2. 按 `u`（pitch←v）→ 再翻腕：`pitch` 不该再跳；抬/落手 → `pitch` 应平滑跟随（方案 B）
3. 想让俯仰仍由腕部驱动：把手**斜拿 45°** → `c` 重采零位 → 按 `t`（roll←psi）→ 只翻腕看 `roll`，只转画面看 `roll` 是否几乎不动（方案 A）
4. 两方案各记一段 jsonl，比较"翻腕时 pitch 的串扰"和"转画面时 roll 的串扰"，取小的那个 → 写进 `calib.json` 按 `w` 保存

## 5. 决定（2026-10-17，主人拍板）

**先不要翻腕，只保留 1 个旋转。**

- 默认改为：`roll.source = theta`（画面内旋转，翻腕/转腕都算"转"）+ `pitch.source = v`（掌心纵向位置驱动 pitch，`v_scale_deg=90`、`gain=0.6`、`deadzone_deg=3`）
- `pitch.source = phi`（旧的翻腕映射）**代码保留但不再是默认**，现场按 `u` 可随时切回对比
- `roll.source = psi`（斜掌方案 A）同样保留为可选
- 结论落点：手部只贡献 **1 个旋转 + 3 个位置 + 夹爪**，第二个旋转由位置补，彻底避开退化

## 6. 方案 6 落地（2026-10-17，主人选：先做方案 6）

**掌朝向 α = atan2( sin 取自法线 , cos 取自掌宽比 )**

```
sin_α = n'_y / hypot(n'_y, n'_z)           # n' = 去旋后的掌面法线（world 3D）
cos_α = clamp( pal_r / palm_r0, -1, +1 )   # pal_r = |p17-p5| / |p9-p0|（纯 2D，掌宽/手长）
α     = atan2(sin_α, cos_α)                # 掌朝向：0°=正对镜头，±90°=侧掌
```

两个观测量的误差互补：正对镜头时法线准、宽度比钝（cos 平坦）；侧掌时宽度比准、法线靠近奇点。

`roll.source` 默认改为 `palm`，映射：
```
roll = roll0 + sign × gain × deadzone(α − α0, 4°)
```
`α0` 与 `palm_r0` 都在按 `c` 采零位时一起记录（`palm_r0` 默认值 0.856，来自 38 张 HaGRID 掌图中位数）。

### 验证：画面内旋转 ±30°（HaGRID 掌图）

| 图 | θ 变化 | α 变化（方案6） | σ 变化（旧 twist） |
|---|---|---|---|
| 0 | −59.5 → −132.2° | −9.6 → −9.2°（**动 2.7°**） | −104.0 → −90.0（动 14°） |
| 1 | −47.0 → −120.9° | −10.8 → −10.6°（**动 3.7°**） | −102.9 → −101.6（动 1.3°） |
| 2 | −65.7 → −139.1° | −14.9 → −16.6°（**动 3.3°**） | −109.5 → −92.9（动 17°） |

α 对"画面内转腕"的敏感度 ≈3°，比 σ 更稳 → 作为默认的 roll 源。

### 换源
`t` 键循环：`palm`（方案6）→ `twist`（绕臂轴）→ `theta`（画面内）→ `psi`（法线出平面）。
CLI：`--roll-source palm|twist|theta|psi`。
