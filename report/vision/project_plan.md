### 0.2 发现的矛盾与疑点(需修订或确认)

1. **A9 版性能定位自相矛盾**:§1 指标"视觉 ~30fps"、§4 预算"A9 版单帧 ≤33ms",但 W1 D3-4 验收只要求"≥15fps"。Cortex-A9(ARMv7 NEON,无 int8 dot 指令)跑 NCNN INT8 效率很低,256×256 CNN 单帧 33ms 基本不可行;15fps 也需要网络极小(建议 ≤30M MACs、输入 128~160)。
   → **建议修订**:A9 保命版门槛 = 15fps(66ms/帧),PL 版目标 = 30fps(33ms/帧)。选型时以 MACs 总数做硬预算。
2. **W1 D2-3 一天半出 bitstream+PetaLinux 镜像**:仅当厂家采集例程 + BSP 现成可用才可行;且依赖摄像头已到货。见 0.4 新增风险。
3. ~~摄像头采购是关键路径~~ **已确认:OV5640 已到货**(主人 2026-10-13 确认)。主路径改为 OV5640 DVP(640×480@60 或 QVGA 高帧),OV7725 不再采购。OV5640 高帧时序风险沿用计划书 §8"高帧率 DVP 时序不稳"应对(退回 30fps)。
4. 表述小矛盾:"方案已与主人逐项确认,方向不再发散" vs §10"执行前向主人确认"。建议措辞改为"确认至默认决策级别"。
5. §1"端到端 ≤200ms"未拆预算:A9 版 33ms 推理下 200ms 很紧。建议拆解:采集 17~33 + 推理 66(A9)/10(PL) + 映射/IK <5 + SYNC_WRITE/舵机响应 ~50~80,并写入 W2 延迟报告。
6. 训练数据来源未写明:公开手部数据集(EgoHands/自采) + 演示场景自录视频;需下载带宽与标注成本评估。
7. 计划书未提舵机供电方案——原仓库已有实物运动日志,供电应已有方案,执行 agent 现场确认即可,不阻塞。
