# 「目标手在窗口外」负样本实验 + INT8 QAT 实测（2026-10-15）

**一句话结论**：想靠"造窗口外负样本"教会模型说"这里没有手"——**没成功**（拒识率 25.9%，目标 ≥90%），
原因是 **val 的窗口外样本真值中位只离窗口边界 7.5px，落在 8~11px 的标注噪声带内，这个判据在 HaGRID 上物理不可学**。
顺手实测的 **INT8 QAT 同样没有收益**（5.48px vs PTQ 5.495px）。两个负结果都有数据支撑，**冻结模型保持 run-5 不变**。
唯一可交付的正收益：加了负样本的模型在**同召回率下精度更好**（窗口内中位 4.44px vs 4.59px），
且 conf 从"没有信息量的常数"变成**可用的难度信号**——给出整条阈值权衡曲线交给控制侧选工作点。

---

## 1. 为什么做（问题定义）

2026-10-14 的评测发现：val 正样本里有 27/564（4.8%）的标注中心**落在部署中心窗口之外**
（短边缩 144 后取 144×144 中心裁剪，竖图的手被裁出去了），这些样本中位误差 **106.17px**、100% 超 8px。
训练侧却因为 `keep_center=True` 保证"窗口一定包含标注中心"，**模型从没见过"窗口里没有目标手"的输入**，
也没有"这里没有手"这个输出状态 → 它只能给一个窗口内的合理点。

冻结模型在这些窗口上的行为（本轮实测，`oob_probe.json`）：

| 量 | 值 |
|---|---|
| 窗口外样本 conf 中位 | **0.9956** |
| conf 最大 | 1.0000 |
| conf > 0.5 比例 | 92% |
| 真值中心离窗口距离 | 中位 7.5px（min 0.3 / max 60px） |

→ 即"手不在窗口里，模型 99.6% 确信它在"。

## 2. 做了什么

### 2.1 造"窗口外"负样本（数据侧，0 额外 MACs）
- `model/common/transforms.py`：新增 `geom_oob()` / `oob_feasible()` / `load_jpeg_oob()`
  - 与正样本同一条缩放规则（短边缩到 size），窗口尺寸取正样本同款缩放抖动 `k = size·U[0.88,1.0]`，
    沿某一轴平移把标注中心推到窗口外 `d ∈ [5%,30%]·k`（另一轴随机取位，与正样本一致）
  - 两段缩放策略（先 `U[0.88,1.0]`，不行再 `U[0.75,0.90]`），50% 水平翻转扩多样性
- `model/detect/dataset.py`：新增 `oob_neg_ratio`（槽位数 = **可用正样本数** × 倍数），
  `_load_oob()` 返回 `conf=0, u=v=0`（train.py 的 uv 损失本来就只对正样本生效）
  - **预筛**：用文件头解析（`transforms.image_size()`，本环境没装 pillow）挑出"确实能把中心推出去"的样本，
    否则绝大多数槽位会退化成普通负样本
  - **验证集完全未受影响**（`augment=False` 时该路径不启用）
- `model/detect/train.py`：新增 `--oob-neg-ratio`，meta 记录 `oob_neg`（ratio / 可用数 / 槽位数 / 实际生效与回退数）

### 2.2 本轮训练规模
| 项 | 值 |
|---|---|
| 可用正样本（能造窗口外负样本） | **1820 / 4454（40.9%）** |
| 训练集 | 8055 = 4454 正 + 1781 普通负 + 1820 窗口外负 |
| 负样本池 | HaGRID no_gesture 1839 + 自录域内 93×5（不变） |
| 配置 | 40 epoch / batch 64 / lr 3e-3 / workers 2 / hm_weight 1.0 / hm_sigma 1.0 / cache256 |
| 训练用时 | 10.5 min（19:33:31 → 19:44） |
| best val median | **4.07px（ep39）**，ep40 4.16px（n=461） |

产物：`_oob.pt`（140KB）、`train_oob_stdout.log`、`*_meta.json`、`*_history.json`。
注：`detect/train.py` 的 meta/history 是写在 `--out` 旁边的，所以它们就在本目录（不是 frozen/）。

## 3. 结果：阈值权衡曲线（核心表）

窗口外 27 / 窗口内 537（val 正样本 564）。**阈值是部署可调的自由参数**，所以整条曲线都给出：

### 旧版（run-5，当前冻结）
| 阈值 | 窗口内召回 | 误拒 | 窗口外拒识 | 窗口内中位 | 窗口内p90 | ≤8px 占比 | 接受数 |
|---|---|---|---|---|---|---|---|
| 0.1 | 99.6% | 0.4% | 3.7% | 4.81px | 43.1px | 64.3% | 535 |
| 0.2 | 98.5% | 1.5% | 7.4% | 4.76px | 43.1px | 64.6% | 529 |
| **0.5** | **95.7%** | **4.3%** | **7.4%** | **4.59px** | **42.9px** | **65.4%** | **514** |
| 0.9 | 81.2% | 18.8% | 25.9% | 4.20px | 34.7px | 69.5% | 436 |

### 新版（+窗口外负样本）
| 阈值 | 窗口内召回 | 误拒 | 窗口外拒识 | 窗口内中位 | 窗口内p90 | ≤8px 占比 | 接受数 |
|---|---|---|---|---|---|---|---|
| 0.1 | 98.9% | 1.1% | 3.7% | 4.63px | 41.5px | 65.7% | 531 |
| **0.2** | **95.7%** | **4.3%** | **11.1%** | **4.44px** | **39.6px** | **66.9%** | **514** |
| 0.5 | 80.5% | 19.6% | 25.9% | 3.94px | 38.2px | 72.2% | 432 |
| 0.9 | 33.5% | 66.5% | 63.0% | 3.97px | 35.8px | 78.9% | 180 |

**判读**：
- **同召回率对比**（都取 ~95.7%）：新版 4.44px / 39.6px / 66.9% vs 旧版 4.59px / 42.9px / 65.4% —— 三项都略好；
  再取 ~81% 召回：新版 3.94px / 72.2% vs 旧版 4.20px / 69.5% —— 也是新版好
- **但拒识目标没达成**：窗口外拒识最高只到 63%（还要把召回砍到 33%）；阈值 0.5 时只有 25.9%
- 新版 conf 整体被压低（窗口外中位 0.9956 → 0.7222），好处是**conf 有了难度区分度**，坏处是默认 0.5 处召回掉到 80.5%

## 4. 为什么拒识学不出来（分层分析）

`analyze_oob_boundary.py` 按"真值离窗口边界多远"分层（阈值 0.5）：

| 组 | 分桶 | n | 拒识率 | conf 中位 |
|---|---|---|---|---|
| 窗口外 | 0-8px | 10 | 20.0% | 0.7130 |
| 窗口外 | 8-16px | 10 | 10.0% | 0.9315 |
| 窗口外 | 32px+ | 3 | 33.3% | 0.7182 |
| 窗口内 | 离边界 0-5px | 5 | 误拒 20.0% | 0.9385 |
| 窗口内 | 5-10px | 14 | 误拒 42.9% | 0.5693 |
| 窗口内 | 10-20px | 32 | 误拒 15.6% | 0.8402 |
| 窗口内 | **20px+** | **486** | **误拒 19.1%** | 0.8091 |

两条决定性证据：
1. **拒识率与"离窗口多远"不单调**（0-8px 反而 20%，8-16px 只有 10%），说明模型没学到"边界"这个概念；
2. **窗口内、离任何边界 20px 以上的样本（486 个）误拒率仍 19.1%** —— 说明这 1820 条负样本起的作用是
   **整体压低 conf 的普通负压**，而不是一个边界规则。

**根因**：val 的窗口外样本真值**中位只离窗口 7.5px**（还有一半更近），而 HaGRID 的 bbox 标注噪声实测是 **8~11px**
（2026-10-14 近重复帧实验：同 user 近重复帧的 GT 中心差中位 11.39px）。也就是说——**"这个点算不算出界"这个标签本身就在噪声里**，
再加上窗口外样本只占 4.8%，模型不可能在这个尺度上学出可用判据。这与该数据集上"≤8px 只能覆盖约 60~65%"是同一个天花板。

## 5. 判定与决定

| 目标（动手前先写死） | 结果 |
|---|---|
| 窗口外拒识率 ≥90% | ❌ **未达成**（最高 63% 且召回崩；常规阈值 25.9%） |
| 窗口内召回@0.5 ≥95% | ❌ 未达成（80.5%） |
| 窗口内中位 ≤5.0px | ✅ 3.94px（阈值 0.5）/ 4.44px（同召回口径） |
| 域内（L1/机械臂）误触发仍 0% | ✅ 见 §7 |
| 抖动 ≤8px | ✅ 见 §7 |

**决定（我的判断，主人授权"你自己决定"）**：
1. **不替换冻结模型**。同召回下的收益（约 0.15px）落在标签噪声内，而代价是部署契约要改（阈值 0.5 → 0.2）
   且召回口径容易被误读。冻结模型保持 run-5（`model/frozen/detect_fp32.pt`，SHA256 `bd6edde3…`）不变。
2. **窗口外失败模式改由系统层解决**，不靠训练：
   - 取景层：4:3 相机只丢水平 25% 视野（u<0.125 / >0.875 才丢），演示工作区居中时不触发；
     若确需覆盖边缘，可改"letterbox 或更大裁剪比"，但输入分布变了要重训（本轮已验证这条路不值得先走）
   - 控制层：演示时人手连续、可加"连续 K 帧一致才动"的时序门（0 MACs），比学边界更可靠
3. **附赠**：阈值权衡曲线交给控制侧当工作点选择依据（同召回下新版更好，但差别很小，直接用旧版 + t=0.5 也完全可以）。

## 6. INT8 QAT 实测：也没有收益

- 入口：`detect/train.py --qat-from frozen/detect_fp32.pt --qat-mode sym`（折叠 BN → val 16 批校准 →
  挂 STE 假量化 → 继续训练；15 epoch / lr 3e-4 / 3.1 min）
- 结果：**best val median（假量化口径）5.48px**，对比 PTQ（`detect/eval.py --int8 sym`）**5.495px** → 无收益
- 解释：固定 scale 的 QAT 只能调权重、调不了激活量化网格；本模型 PTQ 已经把 int8 差距压到 0.5px（float 4.997 → 5.495），
  瓶颈不在权重而在**标签噪声 + 激活逐张量量化**
- 结论：**不建议再投入 QAT**。要继续抠这 0.5px，唯一有意义的方向是"每 N 个 epoch 重新校准激活 scale"，
  但收益上限约 0.3~0.4px，相对 8px 门槛 = 4%，性价比低（已在 LEDGER 记为未做项）

## 8. 踩到的坑（都已修）

1. **`_dequant` 是"量化→反量化"往返函数，入参是浮点**。写 STE 时把量化值又喂进去一次 → 二次量化，
   网络输出从 5.46px 直接崩到 **38.63px**（QAT 第一节就异常）。已加注释 + `_ste` 只做一次往返，
   并验证 `ste=True` 与 `ste=False` 初始化前向完全一致（都是 5.46px）。
2. **OOB 窗口取 `k=size` 时只有 9.5% 正样本推得出去**（HaGRID 标注中心高度集中）。改用正样本同款缩放抖动
   （0.88~1.0）+ 两段放宽（0.75~0.90）+ 预筛，可用率提到 40.9%。
3. **单次随机抽取会失败**（缩放/方向随机）：`load_jpeg_oob` 加"重抽几何、图像只解一次码"。
4. 本环境**没装 pillow**：为读图片尺寸单独引依赖不值，写了 `transforms.image_size()` 直接解析 JPEG/PNG 文件头。
5. 老坑复现：`cd model && ... &` 会把整条链放进子 shell，前台 `tail ../results/...` 会找错目录（要用绝对路径）。

## 10. 复现命令

```bash
cd model && export HAGRID_ROOT=data/cache256
# ① 窗口外负样本训练
python detect/train.py --epochs 40 --workers 2 --hm-weight 1.0 --hm-sigma 1.0 \
    --neg-extra-weight 5 --oob-neg-ratio 1.0 --out ../results/w1_detect_oob/_oob.pt
# ② 阈值权衡曲线 / 分层分析
python ../results/w1_detect_oob/eval_oob.py --weights frozen/detect_fp32.pt ../results/w1_detect_oob/_oob.pt \
    --tags 旧版 新版 --tag oob
python ../results/w1_detect_oob/analyze_oob_boundary.py --weights frozen/detect_fp32.pt \
    ../results/w1_detect_oob/_oob.pt --tags 旧版 新版 --tag boundary
# ③ QAT 微调（固定 scale）
python detect/train.py --epochs 15 --lr 3e-4 --hm-weight 1.0 --hm-sigma 1.0 --neg-extra-weight 5 \
    --qat-from frozen/detect_fp32.pt --qat-mode sym --out ../results/w1_detect_oob/_qat.pt
```
