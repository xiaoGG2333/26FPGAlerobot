# 125MHz / 在线五轴轨迹版本

本轮不增加迭代计时，不下沉完整迭代。PS保留逆解迭代、验收与轨迹规划，
PL保留单步浮点硬件求解。是否通过布局布线，以 reports/optimization_validation.json 为准。

## 文件与回退
- 新工程：build_opt125/rk7100_so101.xpr。
- 新启动文件：boot_opt125/BOOT.BIN（仅构建成功后可用）。
- 原启动文件：reference/pre_opt_20261018/boot/BOOT.BIN。
- 不要混合新旧FSBL、bit和应用；请整体替换BOOT.BIN。
- 出现问题可断电后恢复旧BOOT，并使用旧Ubuntu包。

## Ubuntu操作
先将新压缩包复制到Ubuntu的“下载”目录，再执行：
```bash
source ~/venvs/joycon-rk7020/bin/activate
python -m zipfile -e "$HOME/下载/rk7100_so101_opt125_20261018.zip" "$HOME/"
cd ~/rk7100_so101_opt125_20261018
python -m serial.tools.list_ports -v
python host/xbox_input.py --list
python scripts/verify_board.py --port /dev/ttyUSB1 --servos --out results/read_only.json
```
HELLO需出现 OPT125_SCURVE_20261018_V1，六轴应有有效只读反馈。
只读工具显式查询温度时仍会返回一帧；正常控制不再周期推送温度。
先预览，确认方向及目标有效：
```bash
python -u host/xbox_control.py --port /dev/ttyUSB1 --xbox-device /dev/input/event6 --xbox-right-axes rxry --hz 5 --csv results/preview.csv
```
首次实物验证先托住机械臂、确认短路径，再使用：
```bash
python -u host/xbox_control.py --port /dev/ttyUSB1 --xbox-device /dev/input/event6 --xbox-right-axes rxry --test-drive --manual-control --hz 5 --csv results/drive.csv
```
按Enter后才启用扭矩。摇杆居中后完成最后目标并保持扭矩；Ctrl+C明确停止会关闭扭矩，
退出前需托住。串口、手柄编号按实际列表修改。本轮没有自动执行实物动作。

## 参数
默认规划速度上限：[600,900,900,900,600] 计数/秒。
默认加速度上限：[1200,1200,1500,1800,1800] 计数/秒²。
默认加加速度上限：[6000,6000,7500,9000,9000] 计数/秒³。
轨迹瞬时速度允许为零；ID2～ID4速度寄存器400～900，ID1/5为100～600。
可在驱动命令后追加以下选项，按五轴顺序配置，RAM有效，断电恢复默认：
```text
--joint-max-speeds 600 900 900 900 600
--joint-max-accelerations 1200 1200 1500 1800 1800
--joint-max-jerks 6000 6000 7500 9000 9000
```
首次验证不要直接把全部参数提高到命令允许的极限。默认值是待实物验证的软件预设。

## 实现与保护
轨迹采用参考Ruckig状态约束方式的在线五次Bezier平滑规划，五轴共用时长，
换目标衔接位置/速度/加速度，并验证整段速度、加速度、加加速度及位置边界。
不是Ruckig原库，也不保证时间最优。20ms是名义轨迹服务周期，UART/求解可能推迟服务；
不补发突跳点。舵机内部ACC仍为5，实际跟随需上板验证，不能宣称物理速度已达到900。
逆解终点失败、不可行重规划不替换旧目标；可恢复故障冻结推进并保持扭矩，
恢复后从实际位置重新规划。原映射、编码器限位及舵机55℃超过1.5秒保护不变。
芯片连续高于60℃超过1.5秒冻结新目标；低于55℃且显式恢复后才继续。
传感器故障及硬件OT即时处理保留。风扇55℃全速、50℃恢复50%。
正常日志显示降到约1Hz；--verbose恢复详细显示，CSV仍逐帧保存。
